Detailed Description

Representa o motor de uma única pipeline de processamento de dados.

Esta classe é responsável pelo ciclo de vida completo de uma tarefa de monitorização:

  1. Busca de Dados: Conecta-se a uma main.java.com.gsmart.resources.IDataSource para obter os dados de telemetria mais recentes.
  2. Processamento e Transformação: Aplica as configurações de métricas (main.java.com.gsmart.config.MetricConfig), como aliases e expressões matemáticas.
  3. Avaliação de Regras: Executa o motor de regras para verificar se alguma main.java.com.gsmart.config.AlertRule ou main.java.com.gsmart.config.InsightRule foi despoletada.
  4. Notificação: Comunica alertas e insights através do main.java.com.gsmart.resources.GSmartListener e envia notificações para serviços externos como MQTT e Telegram.
  5. Exportação de Dados: Envia os dados processados para destinos como Power BI ou Microsoft Fabric.
  6. Gestão de Conexão: Lida com a lógica de reconexão automática em caso de falha na comunicação com a fonte de dados.

Cada instância desta classe é executada na sua própria thread, gerida por uma PipelineTask.

Este método é invocado quando a pipeline está a ser terminada para garantir que os dados recolhidos que ainda não foram enviados ou guardados não sejam perdidos.

◆ requestStop()

void main.java.com.gsmart.pipeline.DataPipeline.requestStop ( )

Sinaliza para a pipeline que a sua execução deve ser interrompida.

Este método define uma flag volátil que é verificada a cada ciclo do método run(). Quando a flag é detetada, o loop principal termina, permitindo que a thread encerre de forma graciosa.

◆ run()

void main.java.com.gsmart.pipeline.DataPipeline.run ( )

Inicia e executa o ciclo de processamento contínuo da pipeline.

Este método contém o loop principal que busca, processa e envia dados em intervalos regulares. Ele continuará a ser executado até que o método requestStop() seja chamado.

Em caso de falha de conexão com a fonte de dados, este método entra num modo de reconexão automática, com um tempo de espera exponencial, até que a conexão seja restabelecida ou a tarefa seja interrompida.

Dispara um sinal para que a pipeline tente uma reconexão manual imediata.

Este método é normalmente invocado pela UI quando o utilizador clica no botão "Reconectar Agora" na janela de erro de conexão. Ele define uma flag atómica e interrompe a thread para que o loop de reconexão possa agir imediatamente.
